This repository is a working **development alpha**, not completion of the stable-release acceptance plan. Nothing in the default build or test suite creates billable resources.

## Remaining stable-release gates

1. **Live provider acceptance:** deploy, client join, off-host backup/restore, resize, power-state checks and cleanup on all providers, including Azure expired credentials, actual policy/permission failures, partial ARM failures and residual billing. Supply disposable accounts and a spend budget for those tests.
2. **Complete prices and onboarding:** automated disk/IP/traffic/backup meters, broader onboarding validation, capacity rechecks, and geographic endpoint discovery. Desktop Azure sign-in, subscription selection, installation guidance, and catalog-backed region/size selection are implemented. Public comparison does not require an account or manual VM identifiers. Azure public estimates currently show compute plus an explicit notice for disk/IP/traffic costs. Advanced full-cost estimates still need additional-cost allowances; incomplete totals cannot win total-cost ranking.
3. **Game-aware recovery:** version/mod compatibility matrices, startup verification as part of every change, automatic rollback of failed updates, player-count/game-stat parsing, more validated settings, world preset selection, and explicit join/whitelist acceptance. Current changes retain recovery copies but rollback is operator-driven.
4. **Large transfers and migrations:** resumable/chunked streaming beyond the current 64 MiB JSON/base64 transfer limit, a dedicated migration wizard with destination acceptance, and host-loss drills with remote repositories. Cross-provider migration currently uses explicit backup/restore while retaining the source.
5. **Durable workflow depth:** checkpointed resume and safe cancellation, automatic reconciliation of partial provider creations, complete remote-action polling, and journaling for every direct configuration/file API write. Failed/ambiguous operations currently remain visible for inspection; they are not automatically replayed.
6. **Hosted security review:** expiring sessions, TOTP recovery/enrollment UX, scoped token creation UX, credential rotation, adversarial filesystem/concurrency tests, audited release/runtime verification and host sandbox review. Native mods remain trusted executable code; this is not a hostile multi-tenant sandbox.
7. **Interface and release parity:** named CLI commands and interactive prompts for remaining generic API workflows, complete typed OpenAPI response coverage, hosted execution of the installer workflow, accessibility/browser testing, extracted localization catalog, macOS/Linux installed-desktop tests, signed/notarized artifacts and independent security review.

## Operational limits

- SSH game hosts: Ubuntu 24.04 x64 with .NET 8/10 and a restricted root systemd supervisor. Docker deployments require a Linux x64 engine; local remote-Docker contexts and ARM engines are unsupported. Game processes use a dedicated unprivileged account in both modes.
- One server per VM. Azure world data lives on its managed OS disk; no temporary disk is used. Azure Blob-native backup integration is deferred.
- Azure cleanup never deletes a resource group wholesale. Untagged or externally modified resources are left for inspection, and empty groups remain. Disk/IP charges can continue after deallocation.
- Game sleep alone does **not** reduce cloud VM charges. Azure idle deallocation is off by default, uses a 15-minute default, and requires an external Manager for inactivity monitoring and subsequent wake. Joining a deallocated VM does not wake it; use **Start server** in the Manager. Disk/IP charges remain, and other providers can continue charging for stopped VMs. Azure idle policy cannot be enabled on unsupported game versions; automatic inactivity detection is enabled only for the tested Vintage Story 1.22.0 and 1.22.7 response formats. If detection pauses, the UI surfaces the error and states that compute remains billable. Fresh healthy observations clear the detection error.
- Runtime selection uses the official public stable feed, without a game account login. Supported Linux x64 downloads are stable 1.21/.NET 8 and 1.22/.NET 10. Fresh archives must match the publisher MD5 before extraction; this is an integrity check, not a cryptographic publisher signature. Downloads are verified before stopping a running world. Cached releases remain available for offline restore. Game updates and mod installations remain explicit actions.
- Recovery source limit defaults to 20 GiB and three copies, with free-space checks. Failed staging directories, previous restored data, and trash can consume additional disk and require operator cleanup.
- Console history is currently a 2,000-entry live buffer plus rotated 10 MiB JSONL files, not a full indexed log service with configurable retention.
- No mandatory telemetry, platform billing, automatic updates, Kubernetes, or hosting-company tenancy.
